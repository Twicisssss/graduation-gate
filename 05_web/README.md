# 上位机 / 审计后台（05_web）

## 一、为什么不上云

门禁终端的价值在**认证逻辑本身**，网络只是把日志带出来。把设备直接连公网会引入三个不必要的风险：

| 风险 | 具体表现 |
| --- | --- |
| 校园网认证 | 教室/实验室 Wi-Fi 多要网页 Portal 认证，嵌入式板子过不去，必须开手机热点 |
| TLS 握手 | 云服务强制 HTTPS，小模块做 TLS 吃内存、证书一更新就失效 |
| 现场网络 | 答辩时网络一断，演示直接卡住 |

所以采用**本地优先（local-first）**：

```
门禁终端 ──USB 串口──> 笔记本本地服务 ──> 浏览器面板
                        不联网 / 无数据库 / 无服务器
```

一条命令启动，断网可用，答辩零风险。

## 二、运行

开发机是 **Windows**（Mac 只做文档），所以命令以 Windows 为主：

```bat
cd 05_web\server
pip install -r requirements.txt

py app.py --demo          :: 演示模式，没有硬件也能看效果
py app.py --port COM3     :: 真实串口（设备管理器里看端口号）
```

浏览器打开 <http://127.0.0.1:8000>。

Mac 上（若要临时验证）：

```bash
cd 05_web/server
python3 app.py --demo
python3 app.py --port /dev/tty.usbserial-1420   # Mac 需先装 CH34x 驱动
```

参数：

| 参数 | 说明 |
| --- | --- |
| `--demo` | 不连硬件，按真实比例生成数据（含锁定事件） |
| `--port` | 串口名，Windows 写 `COM3`，Mac 写 `/dev/cu.*` |
| `--baud` | 波特率，默认 115200 |
| `--http-port` | 面板端口，默认 8000 |
| `--snapshot` | 把当前页面渲染成静态 HTML，用于论文截图 |

## 三、功能

- **KPI**：今日通行、拒绝次数、锁定触发、平均认证耗时
- **日志表**：时间 / 用户 / 卡 UID / 阶段 / 结果 / 耗时 / 原因；拒绝行浅红底，锁定行左侧红条
- **耗时柱状图**：最近 14 次，绿色通过、红色拒绝
- **失败阶段构成**：一级读卡 / 二级 PIN / 三级指纹各失败几次
- **导出**：`/export` 下载 CSV（带 BOM，Excel 直接打开不乱码）；同时每 10 s 自动落盘 `logs.csv`

## 四、串口数据格式（固件按此打印）

一行一条，英文逗号分隔：

```
2027-04-02T10:12:33,U01,A1B2C3D4,F3,pass,,2860
时间,用户,卡UID,阶段(F1/F2/F3),结果(pass/deny/lock),原因,耗时ms
```

完整字段与原因枚举见 [固件说明](../04_firmware/README.md#串口日志协议与-pc-后台的契约先定死再写代码)。

## 五、想让老师用手机看

笔记本开热点，手机连同一热点，浏览器访问 `http://<笔记本局域网IP>:8000`。

同一个页面，不改一行代码，不需要蓝牙，也不需要公网。
